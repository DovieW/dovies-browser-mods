# TanStack evaluation for Browser Mods

Reviewed 2026-11-16 against the [public library catalog](https://tanstack.com/libraries). This covers all 19 listed projects, rather than every internal npm package, adapter or historical release. Builder and Stats are website/developer tools outside that library catalog. Nothing in this review installs a dependency or commits the product to a framework.

The recommendations below are project-specific judgments. Popularity is useful when fit is comparable; performance, correctness and maintainability determine fit. Newer packages do not inherit Query's or Table's production history. Catalog badges and documentation can change; recheck the exact package and version at adoption.

## React, Redact and Preact

Redact is a distinct React-compatible browser runtime, not a typo for Preact. It replaces browser React/ReactDOM implementations while preserving React-style application imports. Its public introduction was October 26, 2026, so its track record is much shorter than React's. [Introduction](https://tanstack.com/blog/introducing-tanstack-redact).

| Option     | Reason to evaluate                                                      | Main question for this extension                                                                                         |
| ---------- | ----------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| Native DOM | Current working baseline with no component-runtime dependency           | Does adding more stateful UI make manual rendering and lifecycle code harder to maintain?                                |
| Preact     | Lightweight component model with an optional React compatibility layer  | Do the selected controls/adapters work correctly with the exact Preact version, including events, portals and forms?     |
| React      | Broad component support and interruptible concurrent rendering          | Does that compatibility or scheduling capability justify the actual startup and retained-memory cost here?               |
| Redact     | React-oriented APIs with a smaller browser runtime in upstream fixtures | Do we need its extra React behavior over Preact, and is the newer implementation reliable with our components and build? |

TanStack's pinned comparison reports about 11.2 kB gzip for Preact with compat versus 23.3 kB for default Redact. These retain selected runtime exports, use different functionality, and are not our extension bundle sizes. Redact retains more modern React transition/action behavior than the inspected Preact version, but neither provides React's interruptible rendering. Those differences matter only if our UI uses them. [Pinned comparison](https://tanstack.com/redact/latest/docs/preact).

Smaller output does not prove faster interaction or lower memory. Redact's own performance report contains both wins and losses, and one fixture retains more heap than React. Judge real screens rather than a headline percentage. [Performance report](https://tanstack.com/redact/latest/docs/performance).

Keep the current UI until a representative redesign comparison exists. The documented Redact integrations center on Vite and full-stack frameworks; our build uses esbuild directly. Verify package exports, aliases, feature flags and production output before treating integration as routine. Do not add Start, a server or a second bundler just to obtain a smaller renderer. [Setup](https://tanstack.com/redact/latest/docs/quick-start), [compatibility limits](https://tanstack.com/redact/latest/docs/compatibility).

## Extension-specific limits

**Hotkeys handles keyboard events in documents.** It cannot register Chrome-managed commands, bypass protected browser/OS combinations or assign browser shortcuts programmatically. Chrome allows many commands with at most four suggested defaults; additional assignments belong in `chrome://extensions/shortcuts`. A shortcut recorder can capture desired intent, but must not imply Chrome applied that assignment. Preserve command IDs, observed assignments, desired settings and history as separate concepts. Page-level shortcuts also need site/frame access and cannot cover every restricted page. [Hotkeys behavior](https://tanstack.com/hotkeys/latest/docs/overview), [Chrome commands](https://developer.chrome.com/docs/extensions/reference/api/commands).

**In-memory state is scoped to its context and lifetime.** Store, Query and DB must not create another authoritative copy of synced preferences. Our application service owns reconciliation and persistence; UI subscriptions reflect committed state. A worker may terminate unexpectedly, so queues, timers or cached collections alone cannot guarantee pending work survives. Keep recoverable intent durable and make retries idempotent. A generic persistence adapter must be checked for worker-compatible APIs. [Worker lifecycle](https://developer.chrome.com/docs/extensions/develop/concepts/service-workers/lifecycle).

**Review automatic activity.** Query normally treats cached data as stale, can refetch on mount/focus/reconnect, and retries failures. Polling is optional, not its default. Set a feature-specific freshness/retry policy and invalidate from Chrome events where appropriate; do not let generic defaults turn popup focus into expensive repeated work. Scope and dispose observers, queries, hotkeys and timers. [Query defaults](https://tanstack.com/query/latest/docs/framework/react/guides/important-defaults), [Pacer lifecycle features](https://tanstack.com/pacer/latest/docs/overview).

## Adoption sequence and evidence

1. Keep the separate Zod boundary-validation recommendation in [dependency decisions](dependencies.md).
2. For the UI redesign, implement the same representative settings/command-list slice in disposable native-DOM, Preact, React and Redact fixtures. Include a real dialog/menu if the design needs one; test the exact third-party controls instead of assuming compatibility.
3. Compare production packaged builds: per-context minified bytes, cold/warm time to usable UI, input-to-result latency, keyboard/focus behavior, retained heap after repeated open/close and listener cleanup. Use equal visible behavior, realistic collection sizes and matching hardware/browser. Gzip is an auxiliary comparison, not an installed-extension startup measurement.
4. Evaluate Hotkeys and Form with those actual workflows, then Virtual when list scale warrants it and Pacer when timing/concurrency requirements warrant it. Their adoption decisions are independent; none requires adopting the whole stack. Verify exact framework adapters and peer dependencies for each selected version.
5. Record adopted/deferred status, version, license, transitive inputs, lifecycle ownership and measured cost in the feature decision/PR. Keep component code out of worker/content bundles unless that specific context needs it. Preserve architecture checks and the existing performance policy.

## Completed comparison

The [packaged UI comparison](performance/ui-runtime-2026-11-16.md) and [decision](decisions/2026-11-16-ui-runtime.md) now cover the four standard variants plus three real Radix Dialog integrations. The experiment remains isolated; production now adopts pinned Redact for the workspace shell. See [UI interaction](ui-interaction.md).

The user selected Redact for the redesigned extension-page UI. Its tested interactions and direct-esbuild integration passed. Favor measured performance and fewer future compatibility problems over bundle size alone. The first production workspace slice has its own behavior/performance checks; this comparison does not establish a speedup from replacing native UI. Pin and test adopted control/adapter combinations and verify that native React is not included in Redact bundles.

Do not adopt the tested Preact/Radix combination: it missed 4 of 20 rapid Escape presses. Its 1,000-row unvirtualized warm-readiness tail also crossed the performance review threshold. Redact's newer implementation and compatibility differences still need explicit checks in the actual design. The renderer choice does not require adopting other TanStack packages or imply a universal interaction-speed improvement over React. Measurements, limits and reproduction instructions are linked above.
